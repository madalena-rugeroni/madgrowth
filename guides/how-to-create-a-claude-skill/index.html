How to create a Claude skill (with a working example)

Madalena Rugeroni · Founder of Madgrowth · ex-Google · Updated 17 September 2026 · 8 min read

A Claude skill is a folder with one file, SKILL.md, that tells Claude how to do a specific job and when to do it. To create one, write a short description of when to use it, the steps Claude should follow and what the finished output looks like, then add the folder to Claude Code or upload it as a zip in the Claude app.

The short answer
  • A skill is a folder named after the skill, containing a SKILL.md file with a name, a description and instructions.
  • The description decides whether Claude uses the skill, so it has to say what the skill does and when to use it, in the words people actually type.
  • Good business skills ask for missing inputs first, follow a fixed method and end with an output template, so every run produces the same kind of document.
  • In Claude Code, put the folder in ~/.claude/skills/ for every project or .claude/skills/ for one project. In the Claude app, zip the folder and upload it under Customize > Skills.
  • Test it with five prompts that should trigger it and two that shouldn't, then rewrite the description until Claude picks it at the right moments.

What is a Claude skill, exactly?

A Claude skill is a reusable set of instructions, and optionally reference files and scripts, that Claude loads only when a task needs it. Anthropic's Agent Skills documentation describes three layers. The name and description are always loaded, at roughly 100 tokens per skill. The body of SKILL.md loads when the skill is triggered. Extra files load only when the instructions point to them.

That design is why skills are useful for business work. You can install fifteen of them and Claude only reads the one that fits the conversation. A prompt has to be pasted in every time. A skill waits until it's needed and runs the same method each time.

I build skills for my own businesses and sell a set of them as playbooks in The Stack, so the advice below comes from writing skills that have to produce a document someone can use the next morning.

What goes inside a skill folder?

At minimum, a folder with the skill's name and a SKILL.md file inside it. Anything else is optional.

FileRequired?What it's for
SKILL.mdYesThe frontmatter (name, description) and the instructions Claude follows.
references/*.mdNoLonger material Claude reads only when needed: a framework, examples, a playbook for one type of customer.
templates/NoOutput templates, like a one-page brief or a proposal outline.
scripts/NoCode Claude can run, for calculations that should give the same answer every time.

A simple skill for writing an offer one-liner looks like this:

offer-one-liner/
├── SKILL.md
└── references/
    └── examples.md

How do you write the SKILL.md file?

SKILL.md starts with YAML frontmatter between two lines of three dashes, followed by the instructions in plain Markdown. Here's a complete, working example you can copy and adapt:

---
name: offer-one-liner
description: Writes a one-sentence description of a consulting or fractional offer, plus three variants to test. Use when someone asks for a one-liner, elevator pitch or LinkedIn headline.
---

# Offer one-liner

## Before you write
Ask for anything missing, one question at a time:
1. Who buys this? A role and a type of company.
2. What happens that makes them look for help?
3. What result do they get, in their own words?
4. What proof exists? A number, a past role or a client result.

## Write
- One sentence, under 25 words: who + problem + result + proof.
- Use words the buyer would say out loud.
- Then write three variants: one leading with the result,
  one with the problem and one with the proof.

## Check before answering
- Could a competitor say the same sentence? If so, make the proof more specific.
- Would the buyer recognise themselves in the first five words?

## Output
The one-liner, the three variants, and one sentence on
which variant to test first and why.

The rules for the frontmatter

  • name: lowercase letters, numbers and hyphens, up to 64 characters. Anthropic's docs also reserve the words "claude" and "anthropic", so leave them out of the name.
  • description: what the skill does and when to use it. The developer docs allow up to 1,024 characters, but the Claude help center gives a 200-character limit for skills uploaded to the Claude app. If you want one file that works everywhere, stay under 200.

In Claude Code, the frontmatter can also control who triggers the skill. According to the Claude Code skills docs, disable-model-invocation: true means only you can run it with /skill-name, which is useful for anything you don't want Claude starting on its own.

How do you write a description Claude will actually use?

Write the description as a trigger list: one clause on what the skill produces, then the phrases a person would type when they need it.

Claude compares your request with every installed skill's description and loads the one that matches. A vague description like "helps with marketing" either never fires or fires for everything. Compare these two:

Weak descriptionStrong description
Helps with pricing.Sets a price for a consulting or fractional offer: floor rate, value, three options. Use when someone asks what to charge, day rate or retainer pricing.
Marketing assistant for founders.Writes a LinkedIn content plan: pillars, point of view, weekly cadence. Use when someone asks what to post, for a content strategy or a personal brand plan.

Both strong versions fit in 200 characters, name the output and list the words people use. That second part matters most. People rarely say "value metric". They say "what should I charge".

What makes a business skill better than a prompt?

A business skill is worth installing when it forces a method you'd otherwise skip. In my experience, four things make the difference:

  1. It asks before it writes. List the inputs the skill needs and tell Claude to ask for the missing ones one at a time. Most weak output comes from Claude guessing the customer or the price.
  2. It names the method. Point to a specific framework, such as April Dunford's positioning steps or Blair Enns's three pricing options, and describe how to apply it. "Write good positioning" gives you average positioning.
  3. It has a quality bar. Add a short checklist Claude runs before answering, like the competitor test in the example above. This is where most of the quality comes from.
  4. It ends with a template. Define the exact sections of the output. A skill that produces the same document every time is one you can build a process on.

Once you have more than one skill, a fifth idea helps: give them a shared context file. In The Stack, a setup skill writes the business model, stage and price band to one file, and every other skill reads it, so nobody answers the same questions fifteen times. It also lets each skill load a different reference file for services, software or product businesses instead of stuffing every variant into SKILL.md.

How do you install and test your skill?

Install it where you work, then test that it triggers at the right moments before you trust it.

In Claude Code

  1. Save the folder to ~/.claude/skills/offer-one-liner/ to use it in every project, or to .claude/skills/offer-one-liner/ inside a repository to share it with whoever works there.
  2. Start a session and ask for something that should trigger it, or run it directly with /offer-one-liner.

In the Claude app

  1. Turn on code execution in Settings. Skills need it.
  2. Zip the folder so the skill folder itself is at the root of the zip, with SKILL.md inside it. A zip with SKILL.md loose at the root is the most common upload mistake.
  3. Upload it under Customize > Skills and switch it on. Menu names change, so check the help center if you can't find it.

Skills don't sync between Claude Code, the Claude app and the API, so install the skill separately in each place you use it.

Testing it

  • Write five requests that should trigger the skill, phrased the way a real person would ask, and two that shouldn't.
  • Run them in fresh conversations. If the skill doesn't fire, add the missing phrases to the description. If it fires too often, narrow it.
  • Check the output against your quality bar. When it fails the same way twice, add a line to the checklist rather than hoping for a better run.

What are the most common mistakes?

  • A description that says what, but not when. Claude can't match "A positioning framework" to "nobody understands what we do".
  • One giant skill. A skill that does positioning, pricing and a launch plan triggers at odd moments and produces a long, shallow answer. Split it by output.
  • No questions step. Without it, Claude fills the gaps with plausible guesses and the document looks finished when it isn't.
  • Installing skills you haven't read. Anthropic's docs warn that a skill can direct Claude to run tools or code. Only install skills you wrote or trust, and read every file first.

Questions people ask

Do Claude skills work on the free plan?

According to the Claude help center, skills are available on Free, Pro, Max, Team and Enterprise plans, and they need code execution turned on. In Claude Code, skills are folders on your computer, so there's nothing to upload.

What is the difference between a Claude skill and a prompt?

A prompt lives in one conversation and has to be pasted again next time. A skill is installed once, and Claude loads it automatically when a request matches its description, so the same method runs every time.

Can one skill work in both Claude Code and the Claude app?

Yes, the same folder works in both, but they don't sync. Put the folder in your skills directory for Claude Code and upload it as a zip in the Claude app. Keep the description under 200 characters so the app accepts it.

How long should a SKILL.md file be?

Long enough to hold the questions, the method, a quality checklist and the output template. Anthropic's docs describe the body as usually under 5,000 tokens. Move longer material, like examples or a playbook per business type, into reference files.

Are Claude skills safe to install?

Only if you trust the source. Anthropic warns that a skill can direct Claude to run tools or code, so read every file in a skill before installing it, especially scripts and anything that fetches content from the internet.
